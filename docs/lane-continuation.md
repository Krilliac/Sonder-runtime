# Local host continuation and pending verification

This backend supports explicit host reauthorization of registered interactive-lane parents. It does not automatically resume a model, recover bearer tokens, infer process cleanup from status, or provide distributed ownership. CLI/server composition is separate and must supply the trusted host adapters below.

`LaneContinuationService` requires `authorize_host(context, host_conversation_id)` and a live `model_writable_roots()` inventory. The authorizer must resolve a verified stable host task binding to a `HostContinuationGrant`; a model-provided conversation label or MCP connection ID is insufficient. Without that binding, registration and selection are unavailable. Every admission rechecks the grant, original root/tool ceilings, parent revision/expiry, cancellation and private-store exclusion. The fleet database and its owner-lock directory must be outside every configured model-writable root. Composition must separately exclude the session, approval and host-evidence databases and output-blob storage.

Registration consumes the current root capability only to establish the host binding. It stores no bearer. A kernel owner lock and controlling epoch are published before a private `BoundContinuation` is returned. Raw bearer control of that registered root is thereafter refused transactionally at command admission. Root integrations must also guard parent model/tool admission. Previously admitted independent children retain their own cancellation and budgets when the parent attachment closes.

Fresh selection and `prepare_reattachment` produce an immutable exact approval payload. `execute_reattachment` requires typed real ledger/policy evidence. It cannot take over a live or unknown owner. Repeated pending approval keeps the same prepared payload; a later explicit attachment has a new approval identity and retains prior decision evidence. Unknown approval outcomes do not re-enter the gate. Limits are 1,024 retained bindings per principal, 128 attachment attempts per binding, and 32 retained successful reattachment history entries; these do not reset child execution budgets or original expiry. No archive or deletion behavior is introduced.

`bound.authority_ceiling()` returns safe immutable roots/flags/deadline metadata, not a context or capability. Root constructs a narrowed current context and calls `bound.require_current(context=actual_admission_context)` before each parent model/tool admission. The guard rejects expanded roots, cloud/remote flags, deadlines, altered principal/auth/source or a substituted cancellation token. Backend bound operations use a private attenuated context and never return a reusable context or token. `bound.dispatch` requires an injected trusted `command_codec.decode_command(prepared_host_command)`; its issuer must attest immutable root command preparation, forbidden-field filtering and exact permission approval. It cannot be an external model-dictionary passthrough.

## Original terminal evidence and pending checks

`bound.prepare_verification(verifier, command_id=...)` admits the existing independent check bundle. Before invoking approval, root freezes its original terminal projection and calls `bound.link_pending_verification(verifier, prepared, terminal_projection)`. The required injected `HostProjectionCodec` validates the root's private issuer and full schema. Backend stores exact canonical UTF-8 JSON bytes, SHA-256, continuation/principal/parent/project/verifier binding and revision in the existing scoped lane database. Payloads above 64 KiB, altered retry payloads and scoped-row substitutions fail closed. The host schema owns bounded original output/references, actual parent mutation/validator receipt evidence and original failure class; backend never defaults parent evidence to clean.

`bound.execute_verification` may return `approval_pending` only from `VerificationApprovalPending` carrying confirmed exact pending-ledger evidence. The gate first persists `approval_deciding`; a lost or unexpected gate response becomes non-replayable `approval_unknown / APPROVAL_OUTCOME_UNKNOWN`. A confirmed pending decision has no job intent, clears its owner and releases the verifier barrier. Ordinary execution retries do not ask or spend again.

Only explicit `verifier.resume_pending_approval(bound, identity, approve=...)` may retry that unchanged pending call. It restores the original projection through the trusted codec, revalidates current attachment and original authority, and transactionally checks the complete child/generation snapshot and global workspace overlap before reacquiring the barrier and entering the gate. Accepted steering makes the old bundle stale before approval spend. Repeated premature resume returns the same pending identity and releases the barrier again. Any admitted job or uncertain effect is outside this path. Kernel-proven dead deciding/approved owners with no job intent may release only their barrier during explicit reconciliation; they remain non-replayable unknown outcomes. Read-only recovery pages never perform these transitions.

Root's real ledger bridge alone constructs `PendingApprovalEvidence` or `GrantedApprovalEvidence`. Full digest/tool/surface/expiry must match actual ledger records, not refusal prose or a display prefix. Consumed nonces are real ledger values, separate from policy decision identities. The backend only permits legacy string approval receipts for unregistered ordinary verifier callers.

## Terminal result and recovery

`bound.terminal_projection(identity)` restores the original root evidence. Explicit continuation runs no parent model and accepts no replacement final text. Root computes original parent-effect validity AND fresh delegated validity, preserving original failure/output. A separate `HostTerminalResultCodec` validates that issuer-owned result, binds revision original+1 and reports the digest of the complete immutable verifier certificate. `bound.commit_terminal_projection` checks original link/digest/revision, certificate/bundle/current generation and commits one immutable result receipt. Exact retries replay; conflicts refuse. The stored certificate does not by itself establish parent success.

`recovery_page(context, cursor=0, limit=32)` returns at most 128 bounded metadata entries, including expired original grants visible through fresh authorized host selection. It never flushes model work, starts jobs, acknowledges reports or reconstructs native cleanup evidence. A separate process may reattach only after the old OS lock can be acquired; missing/unreadable locks are unresolved. No timeout or database timestamp establishes takeover authority.

Acceptance uses a scripted model truthfully labelled as such, actual typed file edits, real configured subprocess tests and native cleanup evidence. Tests separately cover real one-shot ledger consume, a separate host process holding the attachment lock, 130-entry read-only recovery pagination, and preserved original parent failure after a real independent certificate. This is local process ownership and bounded observed workspace verification, not HA, an OS sandbox, remote authority or multiwriter memory replication.
