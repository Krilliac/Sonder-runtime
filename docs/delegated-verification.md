# Local delegated verification

`compose_delegated_verification(lanes, process_provider, catalog_path, targets=None)` composes an opt-in host verifier over the existing contained process provider. No model tool or public HTTP route is added. The catalog must satisfy the existing protected-path rules. `targets` is an optional immutable host mapping from exact canonical workspace root string to target name; without it, exactly one target must match each affected root. Missing or ambiguous coverage refuses admission.

The host verifies its parent capability, then calls `prepare(parent_session_id, command_id=..., context=..., bound_parent_revision=...)`. This returns a frozen `PreparedVerification`. Its `approval_payload()` is a fresh JSON-ready bundle containing exact checks, argv/catalog digests, roots, parent revision, steering generation, child revisions/instruction sequences and context fingerprint. The host independently approves this exact bundle through its existing permission policy; child test permission is insufficient.

`execute_prepared(prepared, context=original_context, approve=callback)` calls the approval callback once for a new execution. The callback returns a bounded host approval identity or raises. The service revalidates the catalog and live grants, and the private gateway requires a per-service issuer permit binding the approved bundle to the exact predetermined process call. This path avoids spending a second tool approval and does not disable the ordinary tool gate. Receipts are dictionaries with `state`, `code`, `verification_id`, `parent_session_id`, `generation`, `job_ids` and optional `certificate`. State strings are informational.

Only `validate(parent_session_id, verification_id, context=..., bound_parent_revision=...)` supplies the typed `VerificationVerdict`: `valid`, `code`, `certificate_id`, `generation`, `parent_session_id`, `parent_grant_revision`, `roots`, and `children`. Validation accepts a fresh authorized client context, rechecks live scope and generation, and recomputes the source manifest. Standalone must combine this verdict with its independent validation of parent direct effects; a child certificate cannot prove parent effects.

Parent generations and barriers share the existing fleet SQLite transaction with lane admissions. All lane inserts/saves conservatively advance the generation; exact command replay does not. Admission reads the complete child set (up to256; overflow refuses), rejects owners/queued instructions/pending responses/uncertain effects, and requires explicit process cleanup evidence for prior catalog executions. A barrier fences conflicting local lane dispatch across parent/principal boundaries. Steering stays accepted and visible; it immediately makes the generation stale. Deferred dispatch retains its actual original context/cancellation authority, and does not mint authority from a persisted principal. After process restart, absent in-memory authority requires explicit caller action.

The process provider publishes separate immutable cleanup evidence after observing root exit, native containment empty, native scope/handle closure and resource release. It binds job revision, parent session, principal and process/scope identity. The provider returns no proof for a later changed job revision, missing historical evidence, uncontained execution, failed evidence persistence or uncertain cleanup. Terminal status is insufficient. Windows uses `QueryInformationJobObject` basic accounting plus bounded termination/empty confirmation; closing the handle alone never proves emptiness. Linux retains the existing strong systemd scope requirement. Native API reference: https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-queryinformationjobobject

Workspace manifests stream at most1MiB per read with defaults of16 roots,10000 entries/root,64MiB/file,256MiB aggregate bytes and30seconds per capture. Two complete passes must agree. All regular files, including untracked source, are included except fixed host-policy directory exclusions `.git`, `__pycache__`, `.pytest_cache`, explicitly recorded in the certificate. Links/reparse points, nonregular files, unreadable/changing/oversized/ambiguous trees refuse certification. The aggregate verifier process deadline is at most600seconds and each catalog target keeps its own stricter bounds. This is observed source equality, not an atomic OS snapshot, and does not defeat a malicious external writer's change-and-revert race. Excluded contents and VCS metadata are outside the certificate claim.

`reconcile(...)` never repeats a process or manufactures success. Kernel owner-lock evidence can establish a local controller died; an unknown admitted job still keeps the barrier until explicit durable cleanup proof exists. A crash after actual cleanup but before proof persistence remains incomplete. Failed/expired authority cannot certify. Operator/provider recovery may be required for unresolved native ownership, including a destroyed unnamed historical scope. There is no distributed lease takeover, remote/nested grant expansion or HA claim. Host subprocesses retain OS filesystem/network rights; minimal environment and process containment are not filesystem/network isolation.

Codes: `CERTIFIED`, `NOT_CERTIFIED`, `VERIFICATION_REFUSED`, `CLEANUP_UNRESOLVED`, `RECOVERED_INCOMPLETE`, `STALE_OR_UNAVAILABLE`. Unknown/partial evidence always keeps the delegated result unverified.

## Standalone completion

Standalone completion uses the protected catalog selected by `SONDER_LANE_TEST_TARGETS_FILE`. Exactly one catalog target must match each affected root; ambiguous coverage remains unavailable. After model/tool dispatch stops, the host prepares a separate verification bundle and submits its exact argv and scope to the existing `workspace_run` permission gate. A child lane approval does not authorize this check. No new model-facing action accepts certificate, parent, target, or approval fields.

The controller caches its admission identity and never repeats an ambiguous execution. It consumes only a typed verdict matching its private parent, grant revision, generation, complete child signatures and roots. A fresh manifest validation precedes the terminal decision. Overall validation requires both a current delegated certificate and independent validation after any direct parent mutation or execution effect. Spawning a child does not itself establish a parent-observed file mutation.

Normal completion and delegated early/failure exits share the terminal projector for text, checklist, activity and `HostTaskResult`. Failure markers remain dominant; failure exits do not launch a new verification. Without a usable catalog, permission, quiescent children or cleanup proof, delegated results remain explicitly unverified. A certificate describes included workspace state; it does not certify model prose or task correctness beyond the configured checks.

Schema-1 host receipts optionally include `delegated_verification` with certificate ID, generation, code and `point_in_time_workspace_evidence` scope. Existing nondelegated receipt shapes remain unchanged. This metadata never grants a later effect: consumers acting after the recorded completion must revalidate. Cross-run standalone reattachment is separate work.
