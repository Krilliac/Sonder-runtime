# Private app-control policy prerequisites

This slice adds configuration, private project policy loading, and a pure route transport predicate. It creates no HTTP route, control credential, binding, account grant, or execution authority. Disabled is the default. Host control is a prerequisite, never account authentication.

`SonderConfig.app_control` is loaded only from trusted TOML/explicit host configuration, not environment grant values. It requires an explicit stable `runtime_id`, private absolute `catalog_file`, and `features.host_control=true` when enabled. Session/binding TTLs are absolute ceilings and all session/binding/command/page limits are positive bounded integers. The actual loader adds the catalog path to `private_source_paths`, exposed by Application; diagnostics redact that path. Host composition must include this full source closure in file-tool protection.

`AppProjectGrantCatalog(config_provider=..., workspace_roots=..., private_inventory=..., clock=...)` takes trusted live host providers. `snapshot()` returns immutable `ProjectGrantSnapshot`; `resolve(project, normalized_account, role)` returns immutable `ProjectGrant`. Account and role inputs must come from a freshly authenticated account adapter, never request claims. `require_current(grant)` rereads current config, the anchored catalog, all configured model roots and the full private inventory, and demands exact equality. It grants no authority by itself.

Catalog JSON is at most 256 KiB with exact `{ "version": 1, "grants": [...] }`, at most 64 entries. Each entry has exactly `grant_id`, positive integer `revision`, opaque `project`, normalized unique `accounts`, `role`=`admin`, canonical existing `roots`, exact unique `tools`, boolean `allow_cloud`/`allow_remote`, and finite Unix `expires_at`. IDs/tools are bounded identifiers; projects are handles, not paths. At most 64 accounts, 16 roots, and 64 tools per grant. Cloud/remote true also requires the current global feature/compute ceiling. Root authority is a subset of the full current configured workspace; the catalog parent and every private-source parent must be disjoint from every model-writable root. Private inventory disjointness is independently checked.

The loader holds the existing PrivateDirectoryAnchor and no-follow file handle while reading, rejects nonregular/hardlinked files, limits bytes, compares handle and pathname identity before/after parsing and live policy checks, and rejects duplicate JSON keys/unknown fields. It creates no directories or files. Each grant includes canonical entry digest, raw catalog digest, file identity `(device,inode,size,mtime_ns)`, and runtime ID. Replacement, including identical-byte replacement, fences existing snapshots. Host policy authors must increase revisions monotonically; the future durable binding store must enforce migration/no rollback across process restart. This stateless loader makes no persistent antirollback claim.

`app_control_transport(config, raw_peer=..., origin=...)` is pure and accepts no forwarded headers. Native mode requires explicit `allow_numeric_loopback_native`, numeric loopback listener, numeric loopback raw socket peer, and absent Origin. DNS localhost and wildcard listeners refuse. Browser mode requires exact canonical HTTPS origin separately configured as a subset of CORS, explicit proxy CIDRs matching raw socket peer, TLS termination declaration and `proxy_only_backend=true`. This last field is a deployment attestation: the host must enforce proxy-only backend reachability/network isolation. The predicate cannot cryptographically observe external TLS or configure a firewall. If the host cannot enforce that topology it must keep browser mode disabled or provide a separately reviewed stripped, authenticated proxy proof; forwarded metadata is not such proof. No production handler is enabled here.

Root's later HTTP/control composition must separately apply live exact account-session/password/admin/grant gates, request body/admission bounds, durable credential delivery-unknown semantics, no-store response headers, and live authority revalidation at every admission. It must retain original ceilings and never use a new snapshot to silently expand a binding. This slice does not implement or claim those later controls.
