# WP4 CTX-001/002 — Application context planner

Status: implemented in `sonder_runtime/application/context_planner.py`.

## Contract

`ContextPlanner` is the one application-layer decision point for assembling
context budgets. It is pure and model-aware: the caller supplies the target
model's context window and reserved output capacity, plus measured/requested
token counts. The planner performs no model, network, storage, prompt parsing,
or existing-module integration.

The input budget is:

```text
model context window - reserved output tokens
```

The planner applies each configured section ceiling independently. The sections
are stable instructions, policy, goals/plans, tool schemas, skills, repository
map, working files, recent history, memories, and subagent results. Unspecified
sections, unknown names, negative counts, and non-integer counts are rejected.

If the selected independent section budgets exceed the model input budget, the
planner fails closed. It does not silently evict or rebalance sections; priority,
eviction, and overflow recovery remain CTX-003 and later work.

## Example

```python
from sonder_runtime.application.context_planner import (
    CONTEXT_SECTIONS, ContextPlanner, ModelContext,
)

plan = ContextPlanner().plan(
    ModelContext("local-model", context_window_tokens=16_384,
                 reserved_output_tokens=2_048),
    requested_tokens={"policy": 300, "working_files": 4_000},
    section_budgets={section: 1_000 for section in CONTEXT_SECTIONS},
)
```

Missing requested counts mean zero; every section budget must be explicit. The
returned `ContextPlan` is immutable and exposes both the model-derived input
budget and the final per-section allocations.
