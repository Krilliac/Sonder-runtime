# WP7 TRAIN-005–009: immutable deployment and rollback

This isolated application slice provides the deployment safety boundary for
trained artifacts. `ImmutableArtifact` derives a content digest and rejects a
second payload under the same artifact identity. `DeploymentRollbackService`
requires attended activation and runs a health gate before changing the active
route. A failed gate leaves the prior route untouched. Successful activation
retains the prior route in the event history, and an explicit attended rollback
restores that route while recording a standalone rollback event.

The in-memory repository is a reference adapter for the port; durable storage
must preserve artifact identity, route generations, and append-only history.
This slice does not alter the formal master-spec checkboxes.
