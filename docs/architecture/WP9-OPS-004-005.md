# WP9-OPS-004/005 — Startup reconciliation and graceful drain

Status: implementation slice complete; formal master-spec checkboxes remain unchanged.

`startup_reconciliation.py` defines a persistence-neutral startup boundary for
session, job, subagent, outbox, and activation observations. It recognizes the
existing terminal vocabularies and classifies interrupted, orphaned, pending,
and foreign-owner state without mutating any store.

The drain plan is deliberately bounded. It rejects new work and new claims,
returns explicit resume/delivery/mark-interrupted decisions, and emits only a
non-executing process-tree cleanup intent with a descendant cap. A platform
supervisor is responsible for validating and executing that intent; the
reconciliation policy never invokes subprocess or OS process APIs.

Evidence: `tests/test_wp9_reconciliation.py` covers interruption and terminal
classification, orphan detection, bounded drain behavior, outbox delivery, and
input validation.
