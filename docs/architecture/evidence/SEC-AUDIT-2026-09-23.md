# SEC-001 through SEC-009 acceptance audit (2026-09-23)

Scope: the nine §15 Security requirements of
[`SONDER-MASTER-IMPLEMENTATION-SPEC.md`](../SONDER-MASTER-IMPLEMENTATION-SPEC.md).
Before this audit every one of them had `implemented_unverified` as its latest
ledger revision in [`requirements.jsonl`](requirements.jsonl). Tracking issue:
#510.

Method: for each requirement, find the implementation and the tests that
drive it, check whether any production path calls the implementation, and
compare what the tests prove with the requirement text. The rule applied:
a protection that no test drives is counted as absent, and a contract that no
production path calls does not meet a requirement stated about runtime
behavior. "Test functions" counts `def test_` definitions, not
parametrized cases.

## Status movement from this audit

- SEC-004 moves to `verified`, together with its evidence document and checkbox,
  once the pull-request CI for the implementation commit passes.
- SEC-009 gets a new `implemented_unverified` revision stating the narrower
  remaining gap. It is not verified while the pinned overclaims remain.
- SEC-001, 002, 003, 005, 006, 007, and 008 keep their current ledger
  revisions. This audit supersedes the "implemented" reading of their claims:
  none of them meets its acceptance text yet.

## Suggested next lanes

1. SEC-009 completion: after PR #519 merges, reword the five pinned strings and
   empty `KNOWN_DEBT` in `tests/test_sec009_recovery_boundary_claims.py`.
2. SEC-006: route memory, lesson, and policy writers through
   `evaluate_promotion`, and label web and tool results at ingestion (pure
   Python).
3. SEC-007: one canonical pattern set, with the scanner run at the contribution,
   export, patch, and publication choke points (pure Python).
4. SEC-008: seeded deterministic fuzz suites for the six named targets, with a
   bounded CI job (pure Python).
5. SEC-001: compose `BrokerCredentialProvider` at the bootstrap root and make
   lease release revoke the lease.
6. SEC-002: per-tool egress rules; make the domain policy reject non-canonical
   numeric hosts and `localhost` on its own.
7. SEC-003: a platform adapter that executes `OpenIntent` (native work on
   Windows).

## Limitations

This is a static audit plus the focused tests named above. It is not a
penetration test and does not cover dependencies, the OS, or deployment
configuration. Statements marked "by code reading" were not executed.
