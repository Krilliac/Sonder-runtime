# DATA-007 artifact consumer qualification

This note extends the DATA-004 qualification delta at baseline `ce0291bf`.
Any recovery overlay used during qualification is inherited context; this lane
owns only the focused test and this evidence note.

## Acceptance boundary

The master acceptance for DATA-007 is: bind training, selfmod, update, session
attachments, and generated deliverables to full hashes and manifests. The
latest requirement record (`requirements.jsonl`, DATA-007 revision 2) claims
deterministic canonical hashes at the persistence boundary but explicitly
leaves artifact storage and signing as injected external responsibilities.

## Real producer-to-consumer checks

Command, serial with isolated pytest basetemp:

```text
python -m pytest -q tests/test_data007_artifact_consumer_qualification.py --basetemp=<isolated-temp>
```

Result: **5 passed in 2.86s**.

The first test uses the production update `build_bundle` producer to create a
real on-disk bundle and manifest, reopens the manifest with
`BundleManifest.load`, then changes bytes in the same generated-deliverable
path without changing its name. The production `verify_tree` consumer rejects
the reopened manifest/tree pair with a hash mismatch.

The second test creates a real `ReproducibleTrainingManifest`, persists its
`as_dict()` output, changes the persisted base-model artifact digest, reopens
the manifest, and sends it through `AttendedTrainingExecutionService`. The
consumer recomputes the reopened manifest digest and rejects it before the
training launch side effect. The verifier checks both the signed digest and
the manifest digest presented to the service.

The third test drives the public selfmod lifecycle through a real persisted
SQLite run, backup, candidate workspace, tested-bytes record, review, and
approval. A fresh Python process reopens the persisted run after the candidate
file is changed at the same path. `selfmod.deploy` refuses the candidate before
copying anything into the repository, with the source tree unchanged.

The fourth test uses the production `SQLiteSpillStore` and
`DurableExecutionOutput` path for a persisted session/output attachment. After
reopen, the durable payload is altered in place while retaining its row and
path identity. Both the artifact-handle reader and the provider-neutral spill
reference reader reject the bytes by digest/size mismatch.

The fifth test uses an ephemeral Ed25519 key generated by the test fixture,
the production `SignedManifest` and `UpdateActivation` seams, and a temporary
activation callback. The signed manifest is persisted as JSON and reopened
before a valid activation. Changing release bytes at the same path, changing a
persisted manifest field, or changing persisted signature bytes each fails
before the health/activation callback. The ephemeral public key is explicit
test-only trust; no production trust store, signing default, install, or
network publication is involved.

## Remaining gate

This is positive evidence for update/generated-deliverable, attended training,
selfmod deployment, durable spill/session-attachment, and signed update
activation admission boundaries. It does not close DATA-007: production
artifact storage/signing-key custody, real platform activation helpers, broader
attachment producers, and cross-platform restart qualification remain
external or separate gates. No ledger, master checkbox, or generated status
was changed.
