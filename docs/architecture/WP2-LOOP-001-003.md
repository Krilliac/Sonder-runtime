# WP2 LOOP-001/002/003 — Application loop contract

## Scope

`sonder_runtime.application.loop_contract` defines the contract-only application
boundary for turns, steps, and live interception. It does not modify or
depend on the existing session, event, or cancellation modules.

## Contract

- `TurnContract` and `StepContract` are frozen snapshots. Lifecycle methods return a new value;
  they never mutate the prior snapshot.
- A turn may start, owe and reconcile steps, stop, then complete only when no
  steps remain owed and steering is reconciled. Failure and cancellation are
  terminal states.
- A step contains exactly one model-request lifecycle and the tool calls and
  results caused by it. Completion rejects outstanding tool results; retry
  creates an explicit new attempt.
- `InterceptionPhase` provides typed live seams: `pre_step`, `model_request`,
  `pre_execute`, `execute`, `post_execute`, `turn_stopping`, `error`, and
  `retry`. Execution phases require a step identity.
- `Interception` is live control-plane data, not a durable session event.

## Compatibility boundary

No existing session/event/cancellation interface is changed. Future adapters
may translate these immutable snapshots and interception envelopes into those
systems under separate work packages.
