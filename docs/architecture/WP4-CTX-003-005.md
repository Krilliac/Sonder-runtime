# WP4 CTX-003/005 — deterministic priority and explainability

## Boundary

`sonder_runtime.domain.context.priority` is a pure policy for selecting already
constructed context items. Candidates carry an integer priority, token cost,
source, optional confidence, protected status, and an explicit ordinal for
producer ordering. Selection is ranked by protected status, descending
priority, ordinal, and item id. Items that fit are admitted in that order;
skipping an item that does not fit does not block smaller later items.

Protected items are always retained. If their combined cost exceeds the
budget, the result reports `emergency_overflow` and omits every optional item.
The same policy exposes a stable eviction order: unprotected lower-priority
items first, then older ordinals, then item id. No content is truncated,
summarized, deduplicated, planned, or compacted here.

`Selection.explanations` is the explainability manifest. Every candidate has a
selection/omission reason, cost, source, confidence, priority, and protected
flag. The application façade in `sonder_runtime.application.context_priority`
owns the use-case boundary and returns this immutable manifest without wiring
the policy into existing planner or compaction modules.

## Scope

This slice adds only the domain policy, application façade, focused tests, and
this evidence document. Planner integration, compaction, deduplication,
provider-specific costs, and specification checkbox/evidence-ledger updates
remain follow-up work.
