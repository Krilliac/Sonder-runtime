# WP4 CTX-004/006/009/010 — Context manifests

This slice adds `sonder_runtime.application.context_manifests`. It is a pure,
integration-neutral boundary: callers provide already-rendered context records;
the module does not invoke or modify the existing context planner.

## Contracts

- **CTX-004:** `deduplicate_context()` sorts by producer ordinal and item id,
  retains the first record, removes exact duplicates (line-ending canonicalized)
  and bounded token-Dice semantic duplicates, and records the reason, similarity,
  and both producer sources in `DedupProvenance`.
- **CTX-006:** `LastGoodSnapshot` publishes only complete, validator-approved
  values. Failed refreshes leave the prior revision intact; publication and
  reads are deep-copy isolated and each revision has a deterministic digest.
- **CTX-009:** `build_prefix_manifest()` includes only stable records and sorts
  them by section, item id, and content digest. The versioned digest is the
  reusable prefix key. `PrefixManifestCache` reports hit/write counts.
- **CTX-010:** `build_replay_manifest()` preserves request section order and
  records item ids, sections, content digests, sources, ordinals, prefix key,
  model, and caller metadata in an immutable manifest with a digest.

The API deliberately stores content digests in replay manifests rather than
copying rendered content. A replay executor can resolve those exact records
through its own store and verify the digest before sending a request.
