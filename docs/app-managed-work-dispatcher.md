# Private managed app work dispatcher

`AppManagedWorkDispatcher(authority, workbench, *, lifetime_factory, authorize_dispatch, terminal_eligibility, max_workers=1, max_retained=32)` composes the durable app work store with the host-only prepared workbench. All three callbacks are mandatory trusted bootstrap inputs; there is no default permission or terminal predicate and no public execution route.

`prepare(selection, command_id=..., request=...)` resolves bounded options without model/discovery I/O and stores immutable `PreparedAppWork` under the exact live selection. Work IDs derive from the scoped command, so retries compare the original plan, context policy and authority rather than minting a new ID or extending timestamps. Only one exact granted project root is supported by the existing work port.

`execute(selection, work_id=...)` first reads retained state. Post-admission rows are observational and never invoke approval or submit again. For a prepared row, the required callback authorizes the exact work outside all account/fleet/registry locks. Use the actual `ContinuationApprovalBridge.authorize('workspace_run', dispatch_approval_arguments(work), surface='app-control', expires_at=work.expires_at)`. The safe arguments include the selected project handle, complete work/plan digests and human-reviewable plan; no account-session reference or issuer is included. Returned evidence must match the existing policy engine's full call digest and live expiry, including inside admission.

A bounded executor slot and exact selection lease are reserved before the durable ADMITTED CAS. Only newly admitted work is submitted. The process-local registry is published before submission; its mutex is never held across database or lifetime calls. The worker wrapper commits run-ID binding, creates the actual guarded `ManagedConversationLifetime` view, and commits its exact host-turn link as RUNNING before returning a model-capable view. The prepared workbench retains its original model, tool, permission, context and final-evidence checks.

The original outward result is finalized by the actual lifetime. The trusted callback `terminal_eligibility(lifetime, expected_turn, finalized)` must call the root-owned eligibility service, which reloads sealed evidence and performs any required current certificate publication checks. The dispatcher accepts only the exact `ManagedTerminalEligibility` type with matching finalized result and turn. Only explicit `eligible is True` reaches the terminal store CAS, always with typed `WorkCompletionEvidence` carrying the exact eligibility phase and any original pending identity plus actual publication receipt. The original outward terminal link remains unchanged when a later verification certifies. Missing, denied or uncertain eligibility never implies success. No mock/test predicate is production composition. Recovery semantics remain owned by that service; this dispatcher does not execute approval, verification or a replacement model on status calls.

`status(selection, work_id=...)` reads scoped retained work under fresh authority. It does not reconstruct a lifetime or use stored identity as authority. After accepted dispatch, the dispatcher owns its exact selection until cleanup: request code must not lose that handle or share it with another owner. Prepare/status-only request selections remain caller-owned and must be explicitly released.

Unknown submission may have queued a callback before raising. The dispatcher retains capacity and lease until an actual callback exit is observed; a timeout never proves no execution. A post-admission failure attempts only a bounded unknown-state transition under current authority. If revocation prevents that write, the retained post-admission state remains non-dispatchable. Exception details are not copied into durable interruption evidence. Failed lifetime close retains the exact object and capacity. `retry_cleanup(selection, work_id=...)` retries only local cleanup after proven callback completion; it does not approve, verify, run models or claim native descendant cleanup. `close()` fences new work, drains the owned executor and refuses a clean result while unresolved local resources remain.

This slice provides no HTTP route, automatic restart recovery, timeout ownership stealing, public multi-tenant claim or distributed lease. Tests use real disposable account/control/fleet/session stores, managed host lifetimes and approval ledger with scripted model responses; they do not measure provider quality or remote execution.
