# App authority work transactions and selection ownership

The private `AppManagedAuthority.work_atomic(selection, context, callback)` helper admits the exact issuer-owned selection, takes the account guard before opening the fleet transaction, authorizes the canonical host using that transaction's connection, and borrows the same connection for the bounded app-control callback. It revalidates after the callback and before fleet commit. Callback results are returned only after the fleet transaction completes. Callback/store failure rolls back the fleet transaction; existing store error and uncertain outcome semantics remain authoritative.

Callbacks receive `AppControlTransaction` only. They must perform bounded store operations and return; they must not call model/provider, approval, lifetime, continuation, or recovery operations or wait for another thread. Same-thread authority reentry is refused, including an existing bound check. The helper does not infer a SQLite connection from context-local state. No registry mutex is held while acquiring account or fleet locks.

Selections are process-private authority, not durable IDs. `retain_selection(selection)` creates one opaque work lease; `release_retained(lease)` consumes that exact lease. Double, lost-token substitution and foreign lease release refuse. Losing a lease retains its accounting conservatively; there is no timeout stealing. Neither operation renews original expiry, roots, tools, cancellation or transport authority.

`release_selection(selection)` removes an exact request selection only after all retained leases, parent registrations and active/in-flight admissions are gone. Admission setup is pinned before waiting for the account connection. Cleanup verifies exact issuer and object identity even after expiry or revocation, without granting fresh authority. Expired entries with references are retained; unreferenced expired entries may still be pruned on issuance. Request callers must release their selections; work owners first release their work leases and close the exact parent, then release the selection. A failed cleanup must retain the handle for explicit retry.

These APIs have no public route and do not reconstruct authority after restart. Fresh recovery still requires authenticated issuance under the existing live policy. The helper is a single-host lock-order composition seam, not cross-database account atomicity or a distributed lease.
